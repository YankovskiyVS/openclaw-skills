# Среда OpenClaw 2026.7.1

## Устройство переноса

Версия 2 предназначена именно для файлового хранилища OpenClaw **2026.7.1**. В этом runtime установка нового плагина требует перезапуска. Программа не устанавливает плагины и не меняет конфигурацию Gateway.

Python разбирает выгрузку и сохраняет проверенные источники. JavaScript-помощник загружает SDK уже установленного OpenClaw. Новый файл истории создаётся отдельно от зарегистрированных сессий, с исходными идентификаторами, родителями и датами. `SessionManager` проверяет его как обычную историю. Полностью подготовленный файл публикуется без замены существующего файла, затем `patchSessionEntry` регистрирует только одну новую сессию под штатной блокировкой записи. На время этой операции обслуживание хранилища переводится в режим предупреждений без изменения глобальной конфигурации: миграция не удаляет другие записи из-за их возраста или количества.

Существующая сессия с тем же ключом только проверяется. Дополнительные сообщения, изменение содержимого, другая идентичность или служебные события дают отказ вместо перезаписи. Повторный запуск использует те же ключи. `sessions.json` программа вручную не редактирует; SQL не используется для изменения OpenClaw. Временная SQLite-таблица объединения относится только к самой выгрузке.

Исходная выбранная ветка неизвестна. Последней записывается ветка с самым поздним конечным сообщением. Остальные ветки и независимые корни сохраняются. Доступность переключения ветвей зависит от интерфейса, хотя дерево присутствует в нативной истории.

## Требования

У исторических ответов `usage.contextUsage.state` помечен как `unavailable`: фактический расход токенов в OpenClaw неизвестен. Обязательные счётчики SDK заполнены служебными нулями, включая стоимость. Они не означают измеренный нулевой расход Claude. Размер контекста оценивается средствами SDK по тексту; это позволяет использовать штатную статистику и механизм сжатия без обращения к отсутствующему `usage`.

- Linux/macOS; Python 3.10+, `uv`, `node` и OpenClaw 2026.7.1.
- Запуск на стороне хоста Gateway с доступом на чтение и запись в состояние выбранного агента. Одного доступа к удалённому Gateway по сети недостаточно.
- Постоянные файловые каталоги для состояния, рабочей папки агента и исходного архива. Для разных контейнеров/песочниц доступность одних и тех же файлов проверяется отдельно. S3-адрес не заменяет локальную папку.
- Зависимости Python из `pyproject.toml` заранее установлены через `uv` или доступны в локальном кеше образа. В переносе используется `--offline`; без кеша подготовку образа выполняют отдельно через разрешённый индекс среды. Авторизация Gateway для записи через локальный SDK не используется.

Проверка номера версии строгая. При переходе на другую версию OpenClaw нужен отдельный тест: в новых выпусках хранилище и SDK изменились. Версия 1 с плагином остаётся отдельным пакетом для проверенного runtime 2026.11.3.

## Входные данные

Принимаются один или несколько локальных JSON/ZIP либо явно указанная папка со всеми частями. Пример: `--source first.json second.zip --source third.zip`. ZIP может содержать несколько категорий и вложенные архивы. Общий предел распаковки — 100 GiB, глубина ZIP — 3. Символьные ссылки и пути, выходящие за каталог распаковки, отвергаются. Служебные `.DS_Store`, `__MACOSX`, `.git`, `.venv`, `__pycache__` игнорируются.

Категория определяется по полям JSON: `chat_messages`, `messages`, `docs`, `conversations_memory`, `project_memories`, `memory_files` и другим поддержанным структурам. Имена файлов не обязательны для распознавания JSON. Имена каталогов помогают определить сопутствующие HTML/Markdown артефактов. Неизвестные данные и пустые массивы сохраняются без попытки выдумать их назначение. Одинаковые записи из ZIP и распакованной копии объединяются; разные снимки остаются в архиве. Передача только памяти или метаданных допустима и даёт ноль чатов.

Манифест сохраняется как необязательный исходный файл. URL из него не открываются, отсутствующие части не загружаются. Файлы пользователя не меняются и не удаляются. Программа не содержит сетевого загрузчика. Файловое состояние нельзя подменить удалённым API или S3-ссылкой.

## Параметры

| Параметр / переменная | Назначение |
| --- | --- |
| `--agent` | Агент назначения, по умолчанию `main` |
| `--state-dir` / `OPENCLAW_STATE_DIR` | Состояние выбранной установки |
| `--imports-dir` | Постоянный архив; по умолчанию `<state-dir>/imports/claude-v2` |
| `--env-file` | Файл настроек pydantic-settings |
| `CLAUDE_IMPORT_OPENCLAW_BIN` | CLI OpenClaw, по умолчанию `openclaw` |
| `CLAUDE_IMPORT_OPENCLAW_PACKAGE_DIR` | Корень установленного npm-пакета OpenClaw, если автоматическое определение не сработало |
| `CLAUDE_IMPORT_NODE_BIN` | Исполнитель JavaScript, по умолчанию `node` |
| `CLAUDE_IMPORT_RPC_TIMEOUT` | Срок ответа локального помощника в миллисекундах, 1000–300000; по умолчанию 60000 |
| `CLAUDE_IMPORT_MAX_UNPACKED_BYTES` | Общий максимум распаковки всех ZIP, по умолчанию 100 GiB |
| `CLAUDE_IMPORT_MAX_ARCHIVE_DEPTH` | Максимальная глубина ZIP, по умолчанию 3 |

Выполнение `uv` в режиме `--offline` запрещает сетевую установку зависимостей. Индекс пакетов задаёт среда, персональные адреса и прокси в скилл не встроены.

Память записывается обычными Markdown-файлами. Компактный указатель добавляется к `MEMORY.md` под локальной блокировкой, без усечения существующего файла. Учитывается `agents.defaults.bootstrapMaxChars` (по умолчанию 20000 символов UTF-16); общий бюджет bootstrap и фильтры конкретной сессии также могут ограничивать видимость. Проверяйте `memory_guide_status` и при необходимости читайте каталог файловым инструментом.

В этой версии загрузчик bootstrap обновляет снимок файлов на каждом ходе обычной сессии. Перезапуск для нового `MEMORY.md` не требуется. Другие режимы, например облегчённый контекст субагента, могут не включать этот файл.

Импортёр не вызывает индекс или embeddings. Уже работающий наблюдатель памяти OpenClaw может сам индексировать новые файлы, в том числе через внешнего провайдера. Настройки пользователя не меняются; отсутствие скачивания выгрузки не означает отключение всех сетевых возможностей Gateway.

Все сообщения считываются и проверяются через SDK после регистрации. Семантический поиск и визуальная доступность в конкретном облачном интерфейсе требуют отдельной проверки. Программа не обращается к модели, не вызывает `/compact` или `/reset` и не изменяет глобальные ограничения контекста.

Источники соответствующей версии: [SDK](https://github.com/openclaw/openclaw/blob/v2026.7.1/src/plugin-sdk/session-store-runtime.ts), [читатель истории](https://github.com/openclaw/openclaw/blob/v2026.7.1/src/plugin-sdk/session-transcript-runtime.ts), [управление плагинами](https://github.com/openclaw/openclaw/blob/v2026.7.1/docs/plugins/manage-plugins.md).

Источники памяти той же версии: [Markdown-память](https://github.com/openclaw/openclaw/blob/v2026.7.1/docs/concepts/memory.md), [обновление bootstrap](https://github.com/openclaw/openclaw/blob/v2026.7.1/src/agents/bootstrap-cache.ts), [параметры индексирования](https://github.com/openclaw/openclaw/blob/v2026.7.1/docs/reference/memory-config.md).

Версия пакета — 2.1.3. Незавершённые планы пакета 2.0.0 требуют старого пакета либо новой подготовки в другой рабочей папке. Исходные файлы пользователя сохраняются.

## Продолжение импортированного диалога

При регистрации новой сессии `sessionStartedAt`, `lastInteractionAt` и `updatedAt` устанавливаются во время импорта. Дата исходного диалога остаётся в заголовке и датах сообщений. Это исключает немедленный daily/idle reset из-за возраста выгрузки. Дальше действует обычная политика сброса OpenClaw; постоянное отключение сбросов не выполняется.

На файловой системе без hard links применяется `copyFile` с `COPYFILE_EXCL`: существующий файл не заменяется, копия проверяется до регистрации. Копирование не атомарно; до завершения и проверки сессия не публикуется в реестре. После аварийного обрыва с неполной незарегистрированной копией проверка может остановить повторный импорт; такой файл нельзя автоматически удалять без проверки происхождения. Обычный `cp` с заменой файлов использовать нельзя.

Пакет 2.1.3 предназначен для новых импортов. Он не восстанавливает автоматически сессии, уже сброшенные старой версией. Не запускайте импорт поверх продолженного чата ради восстановления. Сначала сохраните `.jsonl.reset.*`, текущую историю и постоянный архив.

## Python контейнера

Минимальная версия — Python 3.10. Поддерживаются и более новые версии. Для подготовки и запуска используй `uv sync --offline --no-python-downloads --python "$(command -v python3)" --project ...` и `uv run` с теми же параметрами. Это выбирает существующий python3 контейнера, а не автоматически скачанный интерпретатор. Python и зависимости заранее готовятся в образе; сам перенос выполняется без сетевой установки. Виртуальное окружение из другой ОС или с другого компьютера не копируется.
